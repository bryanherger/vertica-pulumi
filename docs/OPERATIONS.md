# Vertica Cluster Operations Guide

This guide covers day-to-day operations for a Vertica Eon Mode cluster deployed with Pulumi. The commands below assume a 3-node AWS Eon Mode cluster created with `scripts/install_vertica_eon.py`.

## Connecting to the cluster

Find the primary node public IP:

```bash
PRIMARY_IP=$(pulumi stack output instance_ips | head -1)
```

SSH to the node:

```bash
ssh -i ~/.ssh/vertica-automation.pem ec2-user@"$PRIMARY_IP"
```

Run vsql as `dbadmin`:

```bash
sudo /opt/vertica/bin/vsql -U dbadmin -d pulumidb -w 'CHANGE_ME_USE_STRONG_PASSWORD'
```

For TCP mode (recommended when running commands remotely), add `-h <primary_private_ip>`:

```bash
PRIMARY_PRIVATE=$(pulumi stack output instance_private_ips | head -1)
sudo /opt/vertica/bin/vsql -h "$PRIMARY_PRIVATE" -U dbadmin -d pulumidb -w 'CHANGE_ME_USE_STRONG_PASSWORD' -c "SELECT version();"
```

## Starting and stopping the database

### Stop the database (flush catalog first)

```bash
ssh -i ~/.ssh/vertica-automation.pem ec2-user@"$PRIMARY_IP" <<'EOF'
sudo /opt/vertica/bin/vsql -h $(hostname -I | awk '{print $1}') -U dbadmin -d pulumidb -w 'CHANGE_ME_USE_STRONG_PASSWORD' -c "SELECT sync_catalog();"
sudo /opt/vertica/bin/adminTools -t stop_db -d pulumidb -p 'CHANGE_ME_USE_STRONG_PASSWORD'
EOF
```

### Start the database

```bash
ssh -i ~/.ssh/vertica-automation.pem ec2-user@"$PRIMARY_IP" \
    "sudo /opt/vertica/bin/adminTools -t start_db -d pulumidb -p 'CHANGE_ME_USE_STRONG_PASSWORD'"
```

Or use `vcluster` with the cluster config generated by the installer:

```bash
ssh -i ~/.ssh/vertica-automation.pem ec2-user@"$PRIMARY_IP" \
    "sudo /opt/vertica/bin/vcluster start_db --config /opt/vertica/config/vertica_cluster.yaml"
```

## Checking cluster health

### List all nodes

```bash
ssh -i ~/.ssh/vertica-automation.pem ec2-user@"$PRIMARY_IP" \
    "sudo /opt/vertica/bin/vcluster list_all_nodes --config /opt/vertica/config/vertica_cluster.yaml"
```

### Query node status

```bash
ssh -i ~/.ssh/vertica-automation.pem ec2-user@"$PRIMARY_IP" \
    "sudo /opt/vertica/bin/vsql -h $(pulumi stack output instance_private_ips | head -1) -U dbadmin -d pulumidb -w 'CHANGE_ME_USE_STRONG_PASSWORD' -c 'SELECT node_name, node_state FROM nodes;'"
```

### Check NMA health

On any node:

```bash
sudo /opt/vertica/bin/manage_node_agent.sh status node_management_agent
sudo curl -k https://localhost:5554/v1/health
```

## Scaling the cluster

### Adding a node

1. Update `vertica.nodes.count` in `config/config_eon.yaml` and run `pulumi up` to create a new EC2 instance.
2. Run the installer against the new node to install Vertica and deploy TLS material, or use `vcluster add_node` after the node is prepared.

Example `vcluster add_node` (run from any existing node):

```bash
ssh -i ~/.ssh/vertica-automation.pem ec2-user@"$PRIMARY_IP" \
    "sudo /opt/vertica/bin/vcluster add_node --config /opt/vertica/config/vertica_cluster.yaml --hosts <new_private_ip>"
```

### Removing a node

```bash
ssh -i ~/.ssh/vertica-automation.pem ec2-user@"$PRIMARY_IP" \
    "sudo /opt/vertica/bin/vcluster remove_node --config /opt/vertica/config/vertica_cluster.yaml --hosts <private_ip_to_remove>"
```

After Vertica removes the node, reduce `vertica.nodes.count` and run `pulumi destroy` for the removed instance. In Eon Mode, ensure you keep enough nodes to cover the shard count.

## Reviving the database

If you destroyed the EC2 instances but kept the S3 communal storage, you can revive the database on fresh infrastructure:

1. Update the config:

   ```yaml
   vertica:
     eon:
       dbinit: Revive
   ```

2. Deploy new infrastructure:

   ```bash
   pulumi up
   ```

3. Install Vertica on the new nodes:

   ```bash
   python scripts/install_vertica_eon.py \
       --config config/config_eon.yaml \
       --ssh-key ~/.ssh/vertica-automation.pem
   ```

The installer detects `dbinit: Revive` and runs `vcluster revive_db` instead of `vcluster create_db`.

## Monitoring

### Database views

```sql
-- Node status
SELECT node_name, node_state, node_address FROM nodes;

-- Active sessions and queries
SELECT * FROM v_monitor.sessions;

-- Resource usage
SELECT * FROM v_monitor.system_resource_usage;

-- Storage usage
SELECT * FROM v_monitor.storage_usage;
```

### System checks on a node

```bash
# Vertica processes
ps aux | grep vertica

# Disk usage
df -h /data/depot /data/catalog

# Memory
free -h

# Vertica ports
ss -tlnp | grep -E '5433|5444|5554|8443'
```

### CloudWatch alarms

Example CPU alarm:

```bash
aws cloudwatch put-metric-alarm \
  --alarm-name vertica-high-cpu \
  --metric-name CPUUtilization \
  --namespace AWS/EC2 \
  --statistic Average \
  --period 300 \
  --threshold 80 \
  --comparison-operator GreaterThanThreshold \
  --dimensions Name=InstanceId,Value=i-1234567890abcdef0
```

## Troubleshooting

### Database won't start after stop

1. Verify all nodes are reachable over SSH.
2. Verify NMA is running on every node:

   ```bash
   sudo /opt/vertica/bin/manage_node_agent.sh status node_management_agent
   ```

3. Verify S3 access:

   ```bash
   aws s3 ls s3://my-vertica-bucket/pulumidb/
   ```

4. Try force start:

   ```bash
   sudo /opt/vertica/bin/adminTools -t start_db -d pulumidb -p 'CHANGE_ME_USE_STRONG_PASSWORD' --force
   ```

### A node is DOWN

```bash
# Restart the node
sudo /opt/vertica/bin/adminTools -t restart_node -d pulumidb -s <private_ip>

# Check logs
sudo tail -100 /opt/vertica/log/adminTools.log
sudo tail -100 /opt/vertica/log/vertica.log
```

### Slow queries

```sql
-- Long-running queries
SELECT * FROM v_monitor.query_plans WHERE is_executing = 't';

-- Resource contention
SELECT * FROM v_monitor.resource_rejection_reasons;

-- Top queries by duration
SELECT query_duration_us, resource_acquisition_us, execution_us
FROM v_monitor.query_profiles
ORDER BY query_duration_us DESC LIMIT 10;
```

### Disk full

In Eon Mode, Vertica manages the depot. If `/data` fills up, you can:

- Increase the EBS volume size and update `compute.aws.additional_volumes`.
- Reduce `vertica.eon.depot_size` (requires database restart).
- Remove old snapshots or non-Vertica files from `/data`.

### Post-installer vsql hangs

The current installer uses `sudo -u dbadmin` and `-h <primary_private_ip>` to avoid `su` password prompts and AWS local socket issues. If you see hangs in older commands, switch to:

```bash
sudo -u dbadmin timeout 60 /opt/vertica/bin/vsql -h <primary_private_ip> -U dbadmin -d pulumidb -w 'PASSWORD' -X -c "SELECT 1;"
```

## Destroying the cluster

1. Stop the database and sync the catalog.

   ```bash
   ssh -i ~/.ssh/vertica-automation.pem ec2-user@"$PRIMARY_IP" <<'EOF'
   sudo /opt/vertica/bin/vsql -h $(hostname -I | awk '{print $1}') -U dbadmin -d pulumidb -w 'CHANGE_ME_USE_STRONG_PASSWORD' -c "SELECT sync_catalog();"
   sudo /opt/vertica/bin/adminTools -t stop_db -d pulumidb -p 'CHANGE_ME_USE_STRONG_PASSWORD'
   EOF
   ```

2. Destroy the Pulumi-managed infrastructure.

   ```bash
   pulumi destroy
   pulumi stack rm eon-test
   ```

3. Delete the S3 bucket separately if you no longer need the data.

   ```bash
   aws s3 rb s3://my-vertica-bucket --force
   ```
